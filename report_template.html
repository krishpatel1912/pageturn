4. Introduction and Problem Statement

4.1 Domain Overview

The convergence of electronic commerce (E-Commerce) and Enterprise Resource Planning (ERP) represents the foundation of contemporary business computing. While commercial platforms like SAP, Shopify, and NetSuite automate global supply chains, their core software mechanics—shopping cart states, coupon engines, tax itemization, and automated stock reconciliation—are frequently hidden behind black-box cloud APIs.

4.2 The Academic Problem

Standard academic projects typically adopt generic Bootstrap or Tailwind templates, producing visually homogenized portals lacking brand authenticity. Furthermore, projects commonly terminate at a checkout mockup without closing the enterprise transactional loop—neglecting real-time warehouse inventory deductions, Indian GST calculations, waybill tracking, and administrative ERP fulfillment.

4.3 The PageTurn Solution

PageTurn is a complete, production-ready, standalone B2C online bookstore and basic ERP suite. Designed with a distinct "editorial magazine meets zine" aesthetic (warm paper-cream background, ink-black typography, neo-brutalist offset shadows, rotating badge, and pure SVG geometric book covers), PageTurn demonstrates the complete transactional lifecycle: from faceted searching and cart accumulation to card Luhn verification, printable tax invoices, and real-time ERP warehouse status fulfillment.

5. Purpose and Objectives

  • Objective 1: Model an Authentic B2C Online Bookstore: Catalogue 26+ curated titles across 6 literary genres with multi-criteria dynamic filtering (genre, price slider, rating, in-stock only toggle).
  • Objective 2: Real-Time Shopping Bag & Dynamic Tax Engine: Implement a slide-in drawer and cart page that computes coupon discounts (READ10, WELCOME20), evaluates free freight thresholds (₹499), and itemizes 5% book GST.
  • Objective 3: Multi-Channel Simulated Payment Processing: Implement Credit/Debit card validation with the mathematical Luhn Algorithm (MOD-10 formula), simulated UPI QR/VPA rails, and Cash on Delivery.
  • Objective 4: Closed-Loop Order Tracking & Printable Documentation: Generate official computer-generated tax invoices with PageTurn branding and model a 4-stage visual order tracking pipeline (Placed → Packed → Shipped → Delivered).
  • Objective 5: Basic Enterprise Resource Planning (ERP) Suite: Construct an administrative panel supporting CRUD catalog updates, warehouse inventory adjustments, order fulfillment, and interactive SVG sales analytics.
  • Objective 6: Deterministic Client-Side Persistence: Synchronize all catalog, cart, user, and order state mutations seamlessly across browser reloads via HTML5 localStorage.

10. E-Commerce and ERP Concepts Demonstrated

10.1 Shopping Cart Architecture & State Lifecycle

The shopping cart functions as the state buffer between exploratory browsing and financial commitment. In PageTurn, cart state is synchronized via React Context with localStorage. Key e-commerce concepts include:

  • Stock Boundary Clamping: Item quantities cannot exceed warehouse availability, preventing overselling.
  • Freight Threshold Subsidization: Implementing conditional free shipping above ₹499 to drive Average Order Value.
  • Statutory Tax Itemization: Separating merchandise subtotal, coupon discounts, freight, and 5% book GST.

10.2 Simulated Payment Gateways & Transactional Integrity

PageTurn simulates real-world payment gateway transactions:

  • Credit Card Processing: Live formatting and client-side execution of the mathematical Luhn Algorithm (MOD-10 formula) to verify card legitimacy before accepting authorization.
  • UPI Protocol: Simulating modern Indian payment rails with interactive QR code visualizers and Virtual Payment Address (VPA) format verification.
  • Atomic Order Placement: Deducting warehouse inventory simultaneously across all line items upon payment approval.

11. Security, Cryptography and Validation Measures

11.1 The Luhn Algorithm (Card Checksum Formula)

To ensure authentic payment gateway simulation, PageTurn incorporates the Luhn Algorithm (ISO/IEC 7812-1). The algorithm verifies identification numbers:

Mathematical Formulation:

Let C = (c_n, c_{n-1}, ..., c_1) represent the card number string.
For each digit c_i from right to left (1-indexed):
If (i % 2 == 0): double the digit (d = c_i * 2). If d > 9, subtract 9.
Sum = Σ modified digits.
The number is valid iff (Sum % 10 == 0).

Attempting to submit an invalid card number triggers an immediate checksum error banner, halting transaction completion.

11.2 Password Complexity Analysis Heuristics

During account registration, a real-time entropy evaluation checks four criteria: 8+ characters, uppercase letters ([A-Z]), numerical digits ([0-9]), and special symbols ([^A-Za-z0-9]). A visual 4-bar indicator updates dynamically, preventing account creation with weak passwords.

11.3 Data Sanitization and Postal Code Validation

All customer form inputs are sanitized to prevent Cross-Site Scripting (XSS). Shipping addresses enforce a strict 6-digit numerical postal PIN code format matching Indian postal conventions.

13. Advantages, Limitations and Future Enhancements

13.1 Key Advantages

  • Zero External Runtime Dependencies: Operates completely offline with zero external image CDNs, guaranteeing reliable evaluation.
  • Distinct Visual Identity: High-contrast neo-brutalist and editorial zine aesthetic stands apart from generic templates.
  • Full Transactional Closure: Bridges front-office retail with back-office ERP supply chain logistics.
  • High Performance: Static production bundle compiles in ~1 second via Vite.

13.2 Limitations

  • Local Storage Scope: Data synchronization is scoped to the browser client; enterprise multi-terminal deployment would require a server-side relational database.
  • Simulated Currency Rails: Transactions are simulated client-side for academic assessment safety.

13.3 Future Enhancements

  • Microservices Backend: Migrating to a FastAPI / PostgreSQL backend with Redis session caching.
  • Live Payment Gateway Webhooks: Integrating Razorpay and Stripe test environments.
  • AI Recommendation Engine: Deploying collaborative filtering algorithms for personalized book discovery.
